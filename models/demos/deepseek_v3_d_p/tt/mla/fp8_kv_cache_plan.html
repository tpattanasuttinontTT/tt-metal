DSA packed FP8 KV cache

Bottom-up, test-driven execution plan and implementation record for DeepSeek V3.2 and GLM-5.1.

Final contract

BF16 mode

One row-major [latent | RoPE] tensor, 576 BF16 values or 1,152 logical bytes per token.

Scaled FP8 mode

One row-major mixed-format tensor: 512 E4M3 bytes, four FP32 scales, and 64 BF16 RoPE values.

656 logical bytes per token

Indexer

Separate cache owned by DSA, unchanged: bfloat8_b in TILE layout.

The primary cache has one persistent tensor in either mode. FP8 is a semantic cache format, selected by module/runtime configuration; it is not inferred from a bare dtype and requires no environment variable.

BF16 latent→per-token 128-wide scales→E4M3 quantize→pack 656-byte row→cache update→sparse gather + scaled SDPA

Execution stages

Stage 0 — CPU feasibility smoke test

complete
  • Use a temporary CPU prototype to validate TT-compatible E4M3 encoding, power-of-two per-block scaling, chunk invariance, zero policy, and preserved BF16 RoPE.
  • Use the result to establish cache and output PCC gates before implementing device kernels.
  • Do not retain a second FP8 reference path: the production tests compare both device cache formats against the canonical BF16 CPU reference, keeping the synthetic suite local and reproducible.

Stage 1 — Storage and movement primitives

complete
  • Support row-major BF16/E4M3 in device zero-fill and padded-cache zeroing.
  • Support opaque row-major E4M3 copies and padded KV updates.
  • Test rotation, partial chunks, multiple slots/layers, program-cache reuse, and raw-byte equality.

Stage 2 — Quantization and packing

complete
  • Extend per-token FP8 cast with opt-in upward power-of-two scale rounding and configurable E4M3 maximum.
  • Pack latent, scales, and RoPE into one mixed-format row on device.
  • Validate shape/dtype/layout and compare every packed byte in the op tests.

Stage 3 — Sparse SDPA consumption

complete
  • Gather each packed row once; retain the latent in BFP8 and RoPE in BF16.
  • Expand four scales into broadcast tiles and apply them during latent reconstruction.
  • Use constexpr compile arguments for cache format and block-cyclic remapping; no feature macros.
  • Cover sentinel boundaries, gather-ring wrap, indexed ND-sharded caches, H=64 multi-query tiles, and malformed inputs.

Stage 4 — MLA integration

complete
  • Allocate BF16 or packed FP8 through SparseKVCacheFormat; GLM-5.1 defaults to packed FP8.
  • Use the same KV stem for full attention and kv_only.
  • Update, all-gather, block-cyclic prefix gather, sparse SDPA, and host reconstruction operate on one primary tensor.
  • Keep the indexer cache tiled bfloat8_b.

Stage 5 — Serving and migration

complete
  • Build one migration-table config for packed KVPE and one for the optional index cache.
  • Size chunks from physical buffer pages, including row alignment.
  • Decode packed mixed-format rows in the device-less producer PCC path.
  • Validate migration/all-gather and both cache formats.

Stage 6 — End-to-end and performance gates

complete
  • Run synthetic chunked MLA and kv_only for DeepSeek V3.2 and GLM-5.1.
  • Require cache/index PCC and final-output PCC thresholds to pass in both BF16 and packed FP8 modes.
  • Profile production H=32 and H=64 op geometries after correctness changes.

Measured results

Measured 2026-07-13 with the warm synthetic perf harness on an 8-chip Blackhole LoudBox, SP=2 × TP=4, FABRIC_2D. The Galaxy targets DS_PERF_CHUNK=5120 and DS_PERF_CACHE=51200 scale to one 1,280-token chunk beginning at a 12,800-token cache prefix (14,080 total allocated tokens) on LoudBox. Times are device-collapsed critical-path kernel sums; sparse SDPA is included in the full MLA time.

Packed scaled FP8 reduces sparse-SDPA time by 28.7% for DeepSeek V3.2 (1.40×) and 18.5% for GLM-5.1 (1.23×). End-to-end sparse MLA improves by 13.0% and 2.6%, respectively; GLM-5.1 remains dominated by collectives. Reproduce through test_sparse_mla_perf.py::test_mla_chunked_perf; each run writes its commit, branch, device, mesh, fabric, build timestamp, and exact command to run_manifest.json.
